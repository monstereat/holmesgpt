# 生产级 AIOps 事故诊断与受控处置平台

## 背景与目标

- 背景：仓库已有 OpenObserve Toolset、NestJS 订单故障源、Python 告警接收器和本地 Compose 演示；接收器使用 `/bin/echo` 替代 Holmes，任务状态仅驻留内存，没有真实调查结果和重启恢复。
- 目标：完成 Roadmap 中的主要功能，交付能按目标环境部署、处理真实生产观测数据，并通过受控授权执行明确生产动作的 AIOps 平台。
- 成功标准：身份/权限、事故状态、可靠调查任务、真实 Holmes 证据、发布/知识关联、审批与受控执行、验证/回退、复盘和评测均能在目标生产环境验证；不把本地 mock 或 `/bin/echo` 结果当成生产验收。

## 范围

- 包含：扩展现有 Python/FastAPI Holmes API；事故与任务持久化及可靠异步队列；生产身份/RBAC；真实 Holmes/OpenObserve 只读调查；Git/CI 发布事件关联；Runbook/历史事故证据；事故工作台；审批、受控动作执行、执行后验证与失败回退；完整复盘；20 例故障评测；生产部署、安全、可观测、备份恢复和运维文档。
- 不包含：无审批的任意 Agent 写操作、模型直接持有生产凭据、未列入动作白名单的生产变更、未经用户授权的真实生产部署/处置。
- 建议方案（待 Plan 以实际代码验证）：Python/FastAPI 扩展 Holmes API；PostgreSQL 保存事故/任务元数据；Redis + Celery 承担重试队列；OpenObserve 继续保存日志/Trace；NestJS 订单服务保留为故障源。若现有 Holmes API 的配置/存储边界不适合该设计，Plan 必须先说明调整方案。

## 用户与行为

### AC-01：告警被安全接收并稳定去重

- 前置条件：本地 Compose 服务已启动并配置非空 Webhook token。
- 操作：提交合法、重复、无 token 和字段超限的告警。
- 预期结果：合法请求进入同一事故；重复请求返回相同事故/任务标识；未授权和无效请求拒绝，不启动调查。
- 验证方式：API 单测与集成测试。

### AC-02：事故和任务可跨进程重启恢复

- 前置条件：PostgreSQL schema/migration 已获用户明确授权并应用于本地演示数据库。
- 操作：创建调查任务后重启 API 或 worker，再查询同一任务。
- 预期结果：事故关联、任务状态、尝试次数和已完成结果仍可查询；未完成任务能被 worker 恢复。
- 验证方式：PostgreSQL 集成测试和 Compose 重启验收。

### AC-03：调查任务具有有界重试和明确终态

- 操作：让 mock Holmes 调用分别成功、瞬时失败、超时和永久失败。
- 预期结果：瞬时错误按计划退避重试；最大次数后进入失败终态；不泄露 stderr/凭据；重复投递不重复创建事故。
- 验证方式：队列 worker 测试和任务状态集成测试。

### AC-04：真实 Holmes 只读调查返回可核验证据

- 前置条件：用户配置模型凭据、OpenObserve URL、只读账户和流白名单。
- 操作：触发订单 HTTP 500 调查。
- 预期结果：Holmes 查询相关日志/Trace；结论引用证据标识/链接及时间范围；无法证明的内容标记为假设；工具不具备写权限。
- 验证方式：有凭据的本地端到端验收；缺少外部凭据时只可报告 mock 验证，不标记 live AC 通过。

### AC-05：操作者能查看事故处理过程

- 操作：打开本地事故工作台并查看待处理、调查中、已完成和失败任务。
- 预期结果：可见告警摘要、Trace ID、任务状态/重试、调查结论和证据；加载、空、错误状态明确；没有处置按钮或隐式写操作。
- 验证方式：浏览器端到端验收。

### AC-06：本地环境和评测可重复

- 操作：按 README 启动项目，运行单元、集成和已知根因回放。
- 预期结果：无需手工改源码即可启动；测试报告区分 mock/live；只报告实际测得的指标。
- 验证方式：全套确定性测试和本地演示记录。

### AC-07：生产身份和权限在每个入口生效

- 前置条件：生产身份提供方、用户/角色模型和租户边界已确认。
- 操作：以不同角色访问事故、证据、审批和执行接口，并尝试跨租户及越权操作。
- 预期结果：服务端按用户身份和资源归属授权；Agent/告警 payload 中的身份字段不作为授权依据；未经授权请求不泄露数据也不产生副作用。
- 验证方式：权限矩阵集成测试和目标身份提供方验收。

### AC-08：生产部署和恢复可重复

- 前置条件：目标生产平台、域名/TLS、密钥管理、网络策略、容量和可用性目标已确认。
- 操作：从受控 CI/CD 发布版本，并演练滚动升级、数据库备份/恢复和应用回滚。
- 预期结果：服务健康/就绪探针、资源限制、密钥注入、迁移顺序、备份恢复和回滚符合目标环境的运维要求；生产发布需单独授权。
- 验证方式：隔离预生产环境的部署演练和恢复演练；不以 Compose 本机启动代替。

### AC-09：生产动作受独立授权、白名单和回退控制

- 前置条件：业务方逐项确认生产动作、动作拥有方的授权接口、审批角色、风险级别和验证/回退规则。
- 操作：分别提交未授权、未审批、重复、取消、成功和执行后验证失败的动作请求。
- 预期结果：服务端执行前重新验证身份、资源权限、动作参数和幂等键；动作由拥有该权限的独立执行器实施；未批准或不在白名单的动作零副作用；执行结果、审批、验证和回退完整审计。
- 验证方式：动作拥有方提供的沙箱/预生产集成测试；生产执行须另行明确授权。

### AC-10：Roadmap 集成功能和评测有生产可核验结果

- 前置条件：Git/CI 提供方、Runbook 来源、是否接 Keep、隔离评测数据和指标阈值已确认。
- 操作：回放发布关联、已知故障、相似告警及不可合并样本。
- 预期结果：发布/事故/任务/Trace 可互查；知识引用可回查；聚类误合并可测；20 例诊断结果与误处置建议按批准阈值统计，mock 和 live 报告分开。
- 验证方式：提供方集成测试、隔离环境评测报告和脱敏验收记录。

## 边界与约束

- Holmes API 保持 Python/FastAPI；NestJS 只保留为示例订单服务和遥测源。
- OpenObserve 保存日志、Trace 与前端错误；PostgreSQL 仅保存事故编排元数据和任务状态。
- Agent 调查默认只读；只有经业务动作拥有方独立授权的执行器能执行白名单动作。Agent 结论或人工审批记录本身不能隐式授权外部写操作。
- 数据库 schema/migration 是用户授权红线：本 Spec 和之后的 Plan 批准不自动授权执行迁移。生产发布/处置也需各自获得明确授权。
- 不提交真实 token、模型 key 或数据库密码，不输出到日志/报告。
- 页面当前为静态 demo；Plan 阶段基于仓库前端结构确定事故工作台落点，不能新增重复的大型前端栈。
