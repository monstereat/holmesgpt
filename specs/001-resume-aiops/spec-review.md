# Spec 独立审查

- 审查范围：`spec.md`、`roadmap.md`
- 审查方式：只读审查；审查人未编辑工件或代码。
- 初审结论：需修改，未发现 P0，发现两项 P1；第一轮复审确认已修复动作拥有方边界，但发现 live 验收表述不一致。

## 问题及处理

### P1：处置动作必须由资源拥有服务授权和执行

- 证据：初版 AC-07 未说明执行器是调用订单服务接口，还是绕过服务直接改资源。
- 风险：执行器可能取得资源拥有服务之外的写权限，违反项目要求的动作授权边界。
- 修复：AC-07 现要求执行器只调用 Compose `order-service` 拥有的受认证动作接口，由 `order-service` 在服务端验证动作、资源、参数和幂等键并实施副作用；禁止执行器通过数据库或容器通道绕过服务。

### P1：真实 Holmes 调查是完整本机验收的必要条件

- 证据：初版 AC-04 把真实验收写成凭据可用时的可选项。
- 风险：仅以 mock 通过，可能把没有真实 Holmes/OpenObserve 调查的项目误报为完整验收。
- 修复：AC-04 现要求 full acceptance 必须完成本机 live 端到端调查；凭据不可用时 AC-04 阻塞，mock 仅验证错误、超时、重试和结果格式。

### P2：评测逐例覆盖范围

- 建议：明确报告记录每一案例的运行模式、证据、诊断、误处置建议和聚类结果。
- 处理：已纳入 AC-10；不设置无根据的模型准确率目标。

### P1：成功标准和 R02 必须要求 live 端到端证据

- 证据：第一轮复审发现成功标准中的“真实 Holmes 可选验收”和 R02 对 live 验收的可选语气，与 AC-04 的完整验收条件冲突。
- 风险：可能仅凭 mock 测试就错误地报告完整验收通过。
- 修复：成功标准现在要求本机 live Holmes/OpenObserve 调查；缺少凭据/端点时相应切片和完整验收保持阻塞/未完成。R02 已明确 mock 只验契约、错误和重试，完整目标需要 live E2E 证据。

## 最终复审结论

- 结论：通过。
- 未发现 P0/P1 遗留问题。
- 确认 AC-04、成功标准和 R02 一致要求 live Holmes/OpenObserve 端到端证据；缺少凭据/端点时相关切片和完整验收阻塞，mock 仅覆盖契约/错误/重试。
- 确认 AC-07 规定由 order-service 拥有的受认证接口服务端授权和执行副作用，执行器不绕过服务写资源。
- 确认本机测试环境与正式环境的授权边界清楚，数据库 schema/migration 仍要求单独授权。
- 可进入 Spec 批准门禁。
