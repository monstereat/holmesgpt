# OIDC 用户受控恢复与会话失效

## 背景与目标

- 背景：管理员可以停用工作台用户，但当前没有受控恢复流程。旧签发的会话目前依赖 `active` 标记失效，若简单重新启用可能复活。
- 目标：有效 OIDC 登录后由管理员审核恢复用户访问，同时确保停用前的会话令牌永久失效，身份角色/资源权限只从 IdP 映射刷新。
- 成功标准：迁移、登录回调、管理 API、工作台操作和审计均通过隔离 PostgreSQL 测试；当前本机测试 Compose 应用新迁移并验证。

## 范围

- 包含：用户 session generation 持久字段；停用时递增；JWT 签发和校验 generation；停用用户完成有效 OIDC 登录时记录待恢复请求；管理员查看并恢复待处理身份；恢复审计及工作台控制；测试、文档和 Roadmap 更新。
- 不包含：绕过 OIDC 的管理员恢复；管理员编辑角色/资源权限；添加本地密码恢复流程；生产部署或生产数据库修改。

## 用户与行为

### AC-01：停用与重新启用不会恢复旧会话

- 前置条件：用户曾登录并已停用。
- 操作：管理员恢复其访问。
- 预期结果：停用事务提交后，所有之后开始鉴权的旧 token 均为 401；版本递增与 active=false 原子提交。已经通过鉴权、正在执行的请求允许完成，不承诺中断在途请求。恢复前后旧 token 仍为 401；用户必须重新通过 OIDC 登录获取新会话。
- 验证方式：隔离 PostgreSQL API 测试覆盖旧 Bearer token 和 cookie，并断言停用事务提交后的请求被拒绝。

### AC-02：恢复须先有有效 OIDC 登录申请

- 前置条件：用户被停用。
- 操作：用户完成 state/nonce/PKCE 及签名验证的 OIDC callback。
- 预期结果：只按当前 IdP group mapping 更新角色和资源范围；首次有效 callback 原子设置待处理时间并记录一条含目标身份信息的审计事件，不发放会话；后续 callback 保留原申请时间且不重复审计；无 pending 请求时管理员恢复返回冲突。
- 验证方式：OIDC 回调签名测试和隔离 PostgreSQL 工作流测试。

### AC-03：仅管理员可恢复待处理用户

- 前置条件：用户已完成有效 OIDC 登录并等待恢复。
- 操作：管理员通过 API/工作台批准恢复。
- 预期结果：通过行锁/条件更新仅将 pending 且停用的目标恢复为 active、清除 pending 标记并追加一条审计；事务原子包含状态变更和审计。并发重复审批最多一个请求成功，其他请求返回 409 且不重复审计；无 pending 或已启用目标返回 409，不存在用户返回 404，非管理员返回 403，未认证返回 401。禁止管理员恢复自身。审计含 actor_id、目标 user_id/username 和事件类型，不包含 token/claims。请求体只能为空对象，多传 role/scopes 等字段返回 422。
- 验证方式：直接 API 权限、状态码、严格请求体校验、并发/重复操作、审计和浏览器脚本语法测试。

## 边界与约束

- 权限映射继续由 OIDC issuer/group mapping 拥有；恢复授权不授予或改变角色。
- 停用只保证其事务提交后开始鉴权的请求失效；已通过鉴权的在途请求可能完成。
- 新旧 token schema 兼容由 `session_generation` 默认值 0 处理。混合运行旧版/新版 API 时旧实例不会校验 `sg`，所以部署流程必须先停止/切走全部旧实例，再允许管理员执行恢复；滚动混跑期间不恢复账号。
- 停用时清除 pending 申请；重复停用不重复递增 generation 或审计。每个账号最多有一个 pending 申请；并发 OIDC callback 只产生一条申请审计且保留首次申请时间。
- 恢复审计事务内记录管理员 actor 与目标身份；失败/冲突请求不创建成功审计。管理员不得恢复自身。
- 审计只记录用户 ID、用户名和操作类型，不记录 token、claims 或秘密。
- 数据库变更通过新增向前迁移完成，不删除或重置现有本机数据。
- 生产 IdP、分发、通知和 break-glass 运维策略仍属于生产目标验收范围。
